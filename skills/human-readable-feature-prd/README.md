# 面向研发团队的功能需求文档 Skill

这是一个用于将**已有产品原型 + 技术方案 + 零散需求资料**整理成**给人看的功能需求文档**的 Agent Skill。

主要面向：

- 产品
- 前端
- 后端
- 测试
- 设计
- 其他参与需求评审和研发交付的人员

## 适用场景

当一个需求已经有基础产品原型，甚至已经有技术方案，但团队还缺少一份能够统一理解的需求文档时，使用本 Skill。

它重点解决：

- 用户完整操作流程是什么
- 页面和交互应该如何表现
- 不同条件下系统应该做什么
- 业务规则如何判断
- 状态如何变化
- 权限有什么差异
- 失败、超时、重复操作等异常如何处理
- 测试如何判断功能已经完成
- 哪些内容仍然需要产品或业务确认

## 不解决什么

本 Skill 不以生成 Coding Agent 的实现规格为目标，也不会默认把文档写成：

- API 清单
- 数据库表设计
- 类 / 函数 / 文件修改计划
- 开发任务拆解
- 完整测试用例集

这些内容应分别由技术方案、实现计划和测试计划承载。

## 文件说明

- `SKILL.md`：Skill 的核心规则和生成流程
- `template.md`：默认中文需求文档模板
- `example.md`：完整写法示例

## 推荐用法

```text
使用 human-readable-feature-prd Skill。

读取当前项目已有的产品原型、技术方案和需求资料，生成一份《XX 功能需求文档》。

文档主要供产品、前端、后端和测试评审、开发和验收使用。
重点梳理：
- 用户完整操作流程
- 页面与交互行为
- 业务规则
- 状态及状态转换
- 权限差异
- 异常和边界情况
- 验收标准

技术方案作为理解约束的输入，不要重复技术实现细节。
无法从现有资料确认的业务规则不要自行补全，统一标记为 [待确认]。
```

## 核心原则

最终文档首先服务于人的理解：

**先看懂整个业务怎么走，再理解每个页面怎么交互，然后明确规则、状态、异常和验收。**

技术方案负责“怎么实现”，本 Skill 生成的需求文档负责“业务和产品应该怎么工作”。
