# 示例：联合调查回传摘要

## 1. 调查目标

确认三个问题：

1. 现有系统中 Agent 执行、配置和状态分别由谁拥有；
2. 外部 Agent 评估方案主要采用哪些模式；
3. 当前方案应复用、集成还是自建哪些能力。

## 2. 内部系统发现

### 已验证事实

- Agent 的构建、Skill 装载、ReAct 循环和 SUB Agent 调用集中在执行侧模块；
- 管理侧模块更适合承载评测集、配置、任务、权限和结果；
- 生产 Agent 运行包含真实业务工具、生产会话和 Trace 副作用；
- 当前缺少一次运行对应的完整不可变配置闭包。

### 对方案的影响

- 在管理侧重建 Agent 执行会产生双实现和语义漂移；
- 评估执行应复用现有执行侧能力；
- 必须在工具、会话和 Hook 边界实现评估隔离；
- 配置快照是可复现性的必要机制，而不是普通审计字段。

## 3. 外部方案模式

### 路线 A：离线数据集与最终回答评分

优点：实现简单、成本低。  
限制：难以验证 Skill、工具轨迹和多轮状态。

### 路线 B：真实 Agent 核心与仿真外部环境

优点：保留决策语义，可验证完整轨迹。  
限制：Mock、隔离和证据采集成本较高。

### 路线 C：生产 Trace 回放

优点：场景真实，适合长尾问题。  
限制：数据治理、漂移和副作用控制复杂。

### 路线 D：线上影子评估

优点：最接近真实生产。  
限制：成本、安全和运行治理要求最高。

## 4. 交叉判断

用户要求评估多轮、Skill、工具和 SUB Agent，单纯最终回答评分不足。

内部代码又显示真实执行逻辑集中在执行侧，因此推荐路线 B：

> 控制面冻结条件并管理任务，执行面复用真实 Agent 核心，以 Mock 替代外部业务环境。

Trace 回放适合作为后续场景来源，不应成为首期执行基础。

## 5. 可复用与自建边界

### 可复用

- 现有 Agent 构建和 ReAct 执行；
- Skill 与 SUB Agent 调用；
- 现有权限和配置查询能力；
- 消息和任务基础设施。

### 可借鉴

- 外部框架的场景定义、轨迹模型和裁判接口；
- 开源项目的评测集版本和结果展示方式。

### 需要自建

- 与现有 Agent 配置闭包匹配的快照；
- 业务工具严格 Mock；
- 生产 Hook 隔离；
- 控制面与现有系统集成；
- 规则裁判和本地证据模型。

## 6. 需要用户确认

1. 首期是否必须支持 SUB Agent；
2. 是否允许第一阶段只提供基础结果页；
3. 是否存在禁止在执行侧运行裁判的部署约束；
4. 哪些生产 Hook 无法替换。
