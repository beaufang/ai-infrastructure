# 示例：Agent 与 Skill 评估方案立论卡

> 此示例用于展示如何从一份细节丰富但主线失焦的设计稿中，提炼整体技术方案的立论。

## 现状

Agent 或 Skill 发生 Prompt、模型、工具或流程调整后，团队缺少统一的离线机制验证完整行为。现有验证更多依赖人工试问、最终回答检查或分散的测试逻辑。

## 核心问题

1. **结果不可信**：只看最终回答，无法判断 Skill 选择、工具参数、多轮状态和 SUB Agent 协作是否正确。
2. **过程不可复现**：评测输入、Agent 配置、Skill、模型参数、知识数据和裁判规则会持续变化。
3. **执行不安全**：真实运行 Agent 可能访问生产工具、写入会话或触发业务副作用。

## 根因

现有系统缺少独立的评估运行边界，也没有同时冻结输入、被测配置、外部环境和裁判规则。评估因此无法兼顾真实性、可控性和可追溯性。

## 核心矛盾

评估既要尽可能保留生产 Agent 的真实决策语义，又不能访问真实业务环境或产生真实副作用。

## 核心判断

不能重新实现一套“测试 Agent”，也不能只对最终文本打分。

应真实运行生产 Agent 的核心决策过程，只在外部边界上替换业务工具和知识数据，并保存完整可观察轨迹。

## 推荐路线

建立控制面与执行面：

- 控制面冻结评测集、被测配置和裁判规则，负责调度、结果和审计；
- 执行面复用真实 MAIN Agent、Skill 和 SUB Agent，以严格 Mock 替代业务工具；
- 规则裁判检查确定性轨迹，LLM 裁判判断语义质量。

方案可以压缩为：

```text
真实决策核心
+ 可控仿真环境
+ 冻结评测条件
+ 完整执行证据
+ 规则与语义双裁判
```

## 首期最小闭环

1. 发布不可变评测集；
2. 冻结被测 Agent 配置；
3. 隔离运行真实 MAIN Agent；
4. 严格 Mock 业务工具；
5. 采集回答和工具轨迹；
6. 执行规则与单一 LLM 裁判；
7. 查看场景级结果。

基线比较、多试次聚合、Skill 禁用对照、人工复核工作流、完整 RBAC 和自动 Trace 回流放到后续阶段评估。

## 本次需要确认

1. 是否认可“真实 Agent 核心 + Mock 外部环境”的评估路线；
2. 是否认可控制面与执行面职责划分；
3. 是否认可首期只形成离线评估最小闭环；
4. 哪些高级能力必须进入首期。
