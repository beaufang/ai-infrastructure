# 外部方案研究指南

## 1. 目标

外部研究用于：

- 识别行业主要方案模式；
- 找到可复用的开源组件和实现；
- 了解官方标准、论文和生产实践；
- 发现 Issue、PR、事故和失败经验；
- 判断自研、采购、集成或借鉴；
- 避免重复造轮子；
- 为候选方案和技术取舍提供证据。

不得在方案确定后只搜索支持当前结论的材料。

## 2. 研究计划

每项研究问题包含：

| 字段 | 说明 |
|---|---|
| 调查问题 | 需要回答什么 |
| 决策影响 | 影响哪个方案选择 |
| 关键词 | 问题词、机制词、架构词和失败词 |
| 优先来源 | 源码、官方文档、论文、案例或社区 |
| 可信度要求 | 需要何种证据 |
| 停止条件 | 搜索到什么程度结束 |

## 3. 搜索词

至少覆盖：

- **问题词**：描述现象；
- **机制词**：描述可能的解决方式；
- **架构词**：描述系统形态；
- **替代词**：搜索不同路线；
- **失败词**：limitations、issue、failure、flaky、scalability；
- **实践词**：production、architecture、case study、lessons learned。

通常同时使用中文和英文。

## 4. 来源优先级

### 一级：直接证据

- 官方代码仓库；
- 官方文档；
- 标准、RFC；
- 原始论文；
- 官方 Release、Roadmap；
- 维护者在 Issue、PR、Discussion 中的说明。

### 二级：生产实践

- 公司工程博客；
- 技术大会公开演讲；
- 架构案例；
- 事故复盘；
- 白皮书；
- 有明确测试条件的 Benchmark。

### 三级：线索来源

- 社区论坛；
- 问答平台；
- 个人博客；
- 社交媒体；
- 聚合站和二手解读。

三级来源用于发现线索，不单独支撑关键结论。

## 5. GitHub 调查

### 候选发现

使用：

- 问题和机制关键词；
- GitHub Topics；
- Awesome 列表；
- 相关组织和维护者；
- 论文或官方文档引用；
- 相似项目的依赖和替代品。

进入深度分析的候选通常控制在 3～8 个。

### 定位判断

检查：

- README 和官方文档；
- 目标与非目标；
- 核心抽象；
- 支持场景；
- 依赖环境；
- License。

淘汰问题不一致或前提明显不匹配的项目。

### 源码验证

围绕调查问题搜索：

- 核心接口和数据结构；
- 执行入口；
- 状态模型；
- 调度与隔离；
- 存储；
- 扩展点；
- 异常处理；
- 测试用例。

不得仅根据 README 判断能力。

### Issue、PR 与 Discussion

主动搜索：

- 已知限制；
- 性能和并发问题；
- 状态与一致性问题；
- 高频需求；
- 被拒绝的设计；
- 长期未解决的问题；
- 重大架构变更；
- 维护者说明的取舍。

### 成熟度

检查：

- 最近 Release 和有效提交；
- 主要维护者；
- PR 和 Issue 响应；
- 版本兼容；
- 重大重构；
- 真实生产用户证据；
- License 和商业限制。

Star 和 Fork 只能作为关注度信号。

## 6. 其他来源

### 官方文档与架构中心

提取通用机制，不直接复制厂商产品组合。标记厂商立场。

### 工程博客与案例

重点提取：

```text
原问题 → 原方案 → 失败原因 → 新判断 → 演进结果
```

### 论文

检查实验条件、数据集、基线、指标、代码和可迁移性。

### 产品文档

用于理解商业产品的能力边界、工作流、集成方式和 Buy/Build 可能性。宣传材料不能单独证明效果。

### 社区讨论

用于发现真实痛点和隐性限制，关键结论尽量回到源码或官方资料验证。

## 7. 外部证据卡

```text
来源：

可信度：

明确限制：

可借鉴：

```

## 8. 方案模式地图

先抽象路线，再映射具体项目。

示例：

```text
路线 A：离线数据集 + 最终结果评分
路线 B：真实执行核心 + 仿真外部环境
路线 C：生产 Trace 回放
路线 D：线上影子评估
```

每条路线说明：

- 核心机制；
- 优势；
- 局限；
- 适用前提；
- 代表项目或实践。

## 9. 适配性比较

根据当前问题选择维度，例如：

- 问题覆盖；
- 与现有架构匹配；
- 可复现性；
- 状态与轨迹能力；
- 隔离与副作用；
- 交付速度；
- 运维复杂度；
- 成熟度；
- License；
- 可复用程度；
- 长期维护成本。

比较后必须明确：

- 推荐采用哪种模式；
- 哪些项目可以直接集成；
- 哪些只借鉴思想；
- 哪些能力仍需自建；
- 外部研究如何改变当前判断。

## 10. 研究回传

向用户回传：

1. 搜索方向；
2. 主要方案路线；
3. 最接近的项目；
4. 已验证和被推翻的假设；
5. 可复用与需自建边界；
6. 外部方案与内部系统的关键差异；
7. 对候选路线和首期范围的影响；
8. 待确认事项。

## 11. 停止条件

当以下条件满足时结束：

- 主要路线已覆盖；
- 至少有两个真实候选；
- 关键结论有一级或二级来源；
- 主要项目已检查源码和已知问题；
- 已确定复用和自建边界；
- 新结果不再改变总体判断。

以下情况不合格：

- 只看 README、Star 或搜索摘要；
- 只搜索支持当前倾向的材料；
- 未搜索替代路线和失败经验；
- 未检查版本、成熟度或 License；
- 搜索了很多项目但没有形成模式地图；
- 没有说明研究如何影响当前方案。
